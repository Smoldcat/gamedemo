# Assets/Debug/ —— 调试工具（发布前请删除）

内部调试工具，**不是给玩家的功能**。所有文件都包在 `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 内，
正式 Release 包里会被编译期剔除（不会打进包）。

## 怎么用

| 操作 | 说明 |
|---|---|
| **`~` 键 / `F1`** | 呼出 / 收起详情面板（双键是为了避开"键盘布局/输入法吞掉 `~`"） |
| 面板位置 | **屏幕左上角、常驻条正下方**（固定，不可拖拽；打开即暂停，所以位置不影响操作） |
| 面板交互 | **纯鼠标**（键盘只用于开关面板） |
| 左上角常驻条 | 一直显示实时数据；可在面板「杂项」里关掉 |
| 详情面板打开时 | **游戏暂停**（这是为了拿到可点的光标，详见下面"为什么"） |

> 进 Play 后 Console 会打印 `[调试工具] 已就绪…` —— 没看到 = 工具没建起来；
> 看到了但按键无反应 = **输入没到游戏窗口**（点一下 Game 视图再按）或被输入法吞掉（改用 `F1`）。

**风格**：终端风 —— **纯黑底 + 绿字**（黄=警告/低血、红=错误/危险），**纯色块 + 1px 线，不使用任何贴图**；
本工具**不依赖游戏的任何视觉资源**（不引用 `BackpackPanel` 的贴图/配色），只依赖它的 public 逻辑入口。

**常驻条（不分页）**：`FPS / 帧时间 / 最差帧 / DrawCall / 三角面` + `血量 / 移速（含三档基准）/ 武器弹药 / 波次·击杀·敌人·金币` + `内存 / 托管内存 / GC 每帧`

**详情面板 = 常驻信息区 + 5 个 tab**（非当前页 `SetActive(false)`，UGUI 不处理 → 省开销）：

| 区域 / Tab | 内容 |
|---|---|
| 常驻信息区 | `HP`（低血变黄、危险变红、无敌/死亡标记）、`移速`（含三档基准、时间缩放）、`武器`（弹匣/弹种等级/备弹）、`魔法`（当前魔法 + 冷却剩余）、`进度`（波次/击杀/敌人/金币/下一波倒计时）—— 两列：**左标签静态、右值每 0.2s 刷新** |
| 战斗 | 满血 / 扣 10 血 / 无敌 / 止血 / 给武器弹药 / 传送到准星 / 走·跑·瞄 三档速度 ± / **杀死玩家** / **射击不耗弹**（持续开关，2026-10-16 新增） |
| 波次 | 秒杀全场敌人 / 跳过清场倒计时 / 金币 +1000 |
| 敌人 | 敌人列表（10 行：名字 / 行为组件 / 血量 / 交战状态 / 距离）+ 测试按钮：**冻结行动**（木桩模式）/ **血量 +500 / ×5 / 恢复默认** / **刷 5 个敌人** |
| **视觉** | 三个**纯显示**开关（2026-10-16 新增）：**视野扇形** / **已发现高亮** / **判定圈**（+ 全部开 / 全部关）。详见下方「可视化」一节 |

**冻结行动（木桩模式）的三个边界（2026-10-15 实测/评审确认）**：
1. 冻结 = 关 `EnemyAI.enabled` + `behaviour.enabled`（每帧压制，新刷出的敌人也会被自动冻住）；**血量组件不受影响**，照常打伤害、头顶血条由工具代刷（0.2s 一次）；
2. **解冻瞬间的语义**：引信已点燃的自爆兵会**立即爆炸**、狙击手会**无预警开火**（它们的计时器在冻结期间照走）—— 解冻前请先躲好；
3. 冻结的敌人**算进"未清场"**（Fighting 阶段波次不推进）；但冻结期间停手超过 ~18 秒，僵局兜底可能把木桩**传送到玩家身边**（WaveManager 既有行为）。另：maxHp 改大后，魔法印记的"血量阈值斩杀"线会随之抬高。
| 物品 | **选一件物品**（◀ ▶ 在物品清单里翻，数量 ±）→ **刷到准星 / 随机刷出 / 给到背包**；外加 **刷个敌人**（从波次敌人池随机） / **商店立即补货** / **清空地上拾取物** |
| 日志 | 游戏内日志（11 行）+ 清空 |
| 杂项 | 时间缩放 0.1x·0.5x·1x·2x / 一键截图 / 常驻条开关 / **清魔法冷却**（一次性归零）/ **魔法无冷却**（持续开关，2026-10-16 新增）/ **相机手感微调**（跟随平滑、前瞄比例、前瞄上限、瞄准收窄，各带 ±） |

底部一行**提示**（黄色）显示最近一次动作的结果（完整文案同时进日志）。

### ⚠️ 四个使用上的取舍（都是被架构约束逼出来的）

1. **时间缩放"关掉面板后才生效"**：面板打开时游戏必须暂停（`timeScale = 0`），此刻写 `timeScale` 会破坏暂停语义；
   而关面板时 `UIState.Pop → GameState.ApplyPause(false)` 又会把它强制重置为 1（`GameState.cs:54`）。
   所以面板只记住"想要的值"，**关闭后由面板每帧写回**（`DebugPanel.ApplyTimeScale`）。
2. **"秒杀全场敌人"后要关掉面板才会进下一波**：`WaveManager.Update` 在暂停时早退，状态机不会推进；
   清完场后必须让游戏跑起来，走完清场倒计时（或倒计时期间再开面板点"跳过清场倒计时"）。
3. **「魔法无冷却」= "每帧把冷却清掉"，不是"让冷却根本不开始"**：Debug 侧**不新增核心方法**（只复用已登记的
   `PlayerMagic.ClearCooldown()`），由 `DebugPanel.SuppressMagicCdTick()` 在**面板关着时**每帧清（和「止血」「冻结行动」同一处）。
   代价：施法那一帧仍会进冷却，而 `HUD.Update` 与 `DebugPanel.Update` 同为普通 `Update`、**执行顺序不确定**
   → 有几率**闪 1 帧遮罩**（肉眼基本不可见）。要"连一帧都不闪"就得往 `PlayerMagic` 加"冷却开关"字段 —— 那属于改核心代码，本工具刻意不做。
   ✅ 实测判据（用 **100 秒**冷却，避免与"自然走完"混淆）：开关**开** → `100 → 0`；开关**关** → `100 → 94.16`（纯自然递减）。
   ⚠️ 开关是**实例字段**（不引入静态、不需要 `StaticReset`）；场景重载后回到"关"（不跨场景保持，与「冻结行动」的"保持"语义不同）。
4. **「射击不耗弹」= "每帧把弹匣补满"，只管弹匣**：和「魔法无冷却」放在同一处（`DebugPanel.Update` 的每帧压制），
   只写游戏**已有的 public 字段**（`PlayerController.weapon` / `magAmmo`）→ **未新增任何核心方法**（登记表仍是 7 条）。
   ⚠️ **语义边界**：它**不碰备弹**（背包里的弹药数量）；但弹匣始终满 → **打不光**，也就**永远轮不到"空弹自动换弹"**
   —— 想专门测那条路径，请先关掉本开关。
   ✅ 实测（反射调用真实 `Fire()` 的 A/B）：关着开关打 3 枪 `30 → 27`；开着开关打 5 枪仍是 **`30/30`**；关掉后手动设 27 会保持 27（不干预）。

## 可视化（2026-10-16 新增，在「视觉」tab 里开关）

| 开关 | 画什么 | 要点 |
|---|---|---|
| **视野扇形** | 每个敌人按 `sightRange × fov` 画半透明扇面；沿弧线打 16 条 `Layers.Blocker` 射线 → **被墙/箱子挡住的部分被削短** | 射线起点与游戏视线同源（`position + 0.4`）；节流 0.12s（**暂停时不重打**）。⚠️ **恒按视野角画**（2026-10-16 决定：不因追击改画整圆，那是过度设计）：游戏**追击时是全向感知**（只有巡逻态才查视野角），所以偶尔会看到"背对玩家、扇形却是红的"——那是**游戏规则如此**（已追到你），不是画错 |
| **已发现高亮** | 看得见玩家的敌人扇形变红 | 读 `EnemyAI.SeesPlayerNow`（**游戏自己的判定结果**），不是 `InCombat` 近似（后者把"4 秒内挨过打"也算进来） |
| **判定圈** | 敌人脚下的**身体判定半径**（`bodyAimRadius`，贴合"点到射线距离"的判定）+ 屏幕空间的**爆头判定圈** | 爆头圈**直接调** `PlayerController.HeadScreenCircle`（2026-10-16 由 `static` 提为 `internal`）→ 与开火判定**同源**，"看到的圈 = 判定的圈"永久成立 |

- **默认全关**（这三样是"世界/屏幕覆盖层"，会盖住大片画面 → 必须手动开；而「常驻条」那种只读数据默认开）。
- 纯显示：不写任何玩法状态、不改数值；`GameState.GameOver` 时自动收摊（避免显示过期读数）。
- ⚠️ **已知边界**：扇形**不体现烟的遮挡**（烟走 `SmokeVolume.BlocksLine` 的几何判定，不是物理射线）；暂停期间射线不重打，所以暂停中改敌人视距不会即时反映。

## 三条硬约束（**改本文件夹前必读**）

1. **单向依赖**：本文件夹只读游戏的 public 成员；**游戏代码永远不许引用 Debug 的任何类型**。
   - 反向依赖是唯一"灾难级"错误：调试代码被 `#if` 剔除后，核心代码会**编译失败**。
2. **零 prefab、零场景改动**：界面靠 `DebugBootstrap` 在运行时创建（`RuntimeInitializeOnLoadMethod`），
   不在任何场景 / prefab 上挂组件 → 删除时不会留下"Missing Script"。
   - 另注：**常驻条必须是独立 Overlay Canvas**（排序 210）。`UIState.Push()` 会隐藏整块 HUD，
     常驻条若挂在 HUD 上会"一开面板自己先消失"（`VirtualCursor.cs:36` 记过这个坑）。
3. **不新增静态状态**：`DebugRead` 只有方法（唯一例外是一个 Unity **原生计数器句柄** `ProfilerRecorder`，进程级共享、不持场景引用，不需要 `StaticReset`）；其余开关一律放实例字段。
   这样"死亡重开 `LoadScene`"不需要任何清理逻辑，也就不用挂 `StaticReset`。
4. **两块画布必须挂在本组件（常驻对象）下**：`UIUtil.NewOverlayCanvas` 建的是**场景根节点**，
   死亡重开 `LoadScene(Single)` 会把它销毁而组件仍在 → 常驻条消失、面板再开会抛 `MissingReferenceException`
   （2026-10-14 评审发现并修复：`_canvas.transform.SetParent(transform, false)`）。

## 为什么详情面板要暂停游戏

不是偷懒，是**UGUI 的硬约束**：

- 游玩态光标是 `CursorLockMode.Locked`（为了无限行程的瞄准）；
- 而 UGUI 在 `Locked` 下会把指针位置**强制写成 `(-1,-1)`**，悬停/拖拽全部跳过，`inputOverride` 也救不了
  → **任何 UI 都点不中**（源码依据与实测见 `Crosshair.ApplyCursorModeNow` 注释、交接文档 #31）；
- 可点的光标模式（`Confined` + 虚拟光标）目前由 `UIState.Push()` 统一负责——它同时会暂停 + 隐藏 HUD。

所以"打开面板就能用鼠标点"与"游戏继续跑"在当前架构下**互斥**（除非新增一套"只切光标不暂停"的核心出口，
那属于改核心代码，本工具刻意不做）。**实时观察的需求由常驻条满足**。
